============================================================
STEP 4 — ORDER CREATION
============================================================

This is the most important backend operation.

Use:

transaction.atomic()

Order creation must be atomic.

Flow:

1. Authenticate user.
2. Get user's cart.
3. Lock relevant cart items / variants where appropriate.
4. Verify cart is not empty.
5. Verify every product is active.
6. Verify every variant belongs to the selected product.
7. Verify every quantity > 0.
8. Verify sufficient stock.
9. Calculate totals server-side.
10. Never trust frontend totals.
11. Validate shipping information.
12. Validate payment method.
13. Generate unique order number.
14. Create Order.
15. Create OrderItems.
16. Decrease stock safely.
17. Clear cart.
18. Commit transaction.
19. Send confirmation email after successful commit.

Use transaction.on_commit() where appropriate for email dispatch.

If anything fails:

- rollback order creation
- rollback stock changes
- DO NOT clear cart
- show useful error message

============================================================
STOCK SAFETY
============================================================

This must be race-condition aware.

Do not simply:

variant.stock -= quantity
variant.save()

without considering concurrent orders.

Use:

select_for_update()

inside transaction.atomic() when reserving/decreasing stock.

Example conceptual flow:

transaction.atomic():
    lock variant
    verify stock
    decrease stock
    create order item

Never allow:

stock < 0

If stock is insufficient:

Do not create the order.

Show a user-friendly message.

============================================================
CART CLEARING
============================================================

Cart must only be cleared AFTER successful Order + OrderItems creation
and stock update.

If order creation fails:

Cart must remain unchanged.
