## GAP DETAIL (audit finding → resolution)

1. **Cart clear missing** → `cart:clear` route + `clear_cart` view (POST, `@login_required`, owner-scoped via `user=request.user`) + confirmation-guarded "Clear cart" button in the cart summary.
2. **Address book missing** → new `Address` model (owner FK, Bangladesh phone validator, `is_default` with single-default invariant in `save()`), migration `accounts.0002_address`, `AddressForm` (premium widgets), views `address_list / address_add / address_edit / address_delete / address_set_default` — every lookup filtered by `request.user` (foreign IDs → 404), delete promotes a remaining default, set-default wrapped in `transaction.atomic()`, admin registration, templates `address_list.html` + `address_form.html`.
3. **Checkout saved-address selection missing** → checkout GET prefills delivery fields from the default address, context gains `addresses`, and a radio picker (first = default) fills the form client-side via `site.js` (`data-address-json`, JSON-escaped with `escapejs`).
4. **Account section templates missing** → `account.html` rebuilt: profile details, recent orders with live count + status chips, saved-address summary, quick actions (My orders / Addresses / Change password / Sign out). The old "My orders — Coming soon" placeholder is gone.
5. **Change password missing** → `PasswordChangeForm` (premium widget mixin, correct autocomplete tokens), `change_password` view using `update_session_auth_hash` so the session survives, route `/account/password/`, template `password_change.html`.
6. **Contact form stored nothing** → `ContactMessage` model (name, email, optional BD phone, message, `is_read`), migration `store.0003_contactmessage`, real `ContactForm` validation (name/email/phone/message), view persists + redirects with success toast, template renders bound widgets + field errors, admin list/filter/search.
7. **`seed_data` command missing** → `apps/store/management/commands/seed_data.py`, idempotent (`get_or_create` on every row): 7 spec categories (Jeans, Shirts, Polo T-Shirts, T-Shirts, Chinos, Jackets, Accessories), 10 realistic products (4 featured), variants with sizes 28–42 for denim and S–XXL for tops, colors Black/Blue/Navy/White/Gray/Beige/Green, stock 12. No user accounts, no fake reviews (spec hard rule).
8. **Error pages missing** → branded standalone `templates/404.html`, `403.html`, `500.html` (site palette, reversed `{% url %}` links) — render even when URL resolution itself fails.
9. **Checkout double-submit** → `data-disable-on-submit` + `data-busy-text` guard in `site.js` applied to the checkout form; generic `data-confirm-submit` confirmation also powers Clear cart and address Delete.
10. **Postgres leftovers** → `dj_database_url` import + `DATABASE_URL` branch removed from `config/settings.py` (SQLite-only, per hard rule), `dj-database-url`/`psycopg` dropped from `requirements.txt`, `DATABASE_URL` removed from `.env.example`.
11. **Test config** → `exportzone/pytest.ini` added (`DJANGO_SETTINGS_MODULE = config.settings`); Django runner remains primary.
12. **URL restructure (§42)** → accounts included without the `/accounts/` prefix (`/register/`, `/login/`, `/logout/`, `/account/...`, `/forgot-password/`, `/reset-password/<uidb64>/<token>/`), orders at `/checkout/`, `/order-success/<n>/`, `/account/orders/...`, product at `/product/<slug>/`. Namespaces preserved; all templates/tests use `reverse()`/`{% url %}`, so path changes were safe (one raw email-link assertion updated).
13. **Nav spec fidelity (§22)** → header/footer categories ordered Jeans → Shirts → Polo T-Shirts → T-Shirts first (`Case/When` in `footer_categories`), "Collections" link added to desktop + mobile menus.

## DELIBERATE SPEC DEVIATIONS

- Reset links keep Django's secure `<uidb64>/<token>` pair instead of the spec's single `<token>` (a bare token cannot identify the user securely). The spec's email-verification step (§10) was removed at the product owner's request: accounts are usable immediately and `/verify-email/...` no longer resolves; `is_active` still lets staff block an account, and deactivated users cannot sign in.
- Logout stays POST-only (CSRF-protected) rather than a bare GET link.
- SQLite only; no Postgres path remains (spec hard rule), so production notes cover backup instead of connection pooling.
- No header link to the orders list (spec's header shows only Search/Account/Cart); orders stay reachable from the account dashboard and mobile menu.

**Verification round 3 (email-verification removal + Show-password fix + welcome email):** (1) the email-verification gate was removed on request — `RegistrationForm.save()` no longer creates `is_active=False` accounts, the "Please verify your email before logging in." branch was deleted from `LoginForm.clean()`, and `views.verify_email` / `verification_sent` / `verification_success`, their three `/verify-email/...` routes, `apps/accounts/tokens.py` and `templates/accounts/verification_*.html` were all deleted (deactivating an account in Django admin still blocks sign-in, now with the generic "Invalid email/phone or password." message). (2) Registration now sends a new branded `templates/accounts/emails/welcome_email.html` through `emailing.send_welcome_email()` — gold-on-ink, table-based, with the member's name, sign-in details, "START SHOPPING" call to action and a readable plain-text alternative that lists the shop/login/contact URLs (entities unescaped) — and the login page shows the "account created successfully" toast. (3) The storefront "Show" password toggle was dead on `/login/`, `/register/` and `/account/password/` because those buttons carried no `data-password-toggle` attribute for `static/js/site.js` to read (only the reset form had it); every password field now nests a `.password-field` wrapper with `data-password-toggle="<input id>"` + `aria-pressed`, and the toggles are covered by tests.

**Verification round 4 (admin-console walkthrough — one defect found and fixed):** driving the admin dashboard end to end against the live server (create category → create product with a variant → place an order → walk its status Pending→Confirmed→Processing→Shipped→Delivered) surfaced one real defect: Django's stock `console.EmailBackend` writes through the console codec, and Windows consoles are cp1252, so any message containing the taka sign (৳) raised `UnicodeEncodeError: 'charmap' codec can't encode character '\u09f3'`. Because both senders swallow errors, the failure was silent — six emails in one session ("Could not send order confirmation…" ×2, "Could not send status update email…" ×4) never reached the mailbox while the UI still reported success. Resolution: `apps/core/email_backends.py` adds `UTF8ConsoleEmailBackend`, which writes the rendered message's raw UTF-8 bytes to the stream buffer (falling back to a lossy decode when no buffer exists); `config/settings.py` maps the configured stock console backend onto it and leaves any SMTP backend untouched, so a future Gmail/SMTP switch needs no code change. Covered by `apps/core/tests.py` (non-ASCII body survives a cp1252 stream; the stock backend is asserted to fail on the same stream). Verified live after restart: the console log now contains the complete `Export Zone — Order Confirmed #EZ-…` message including `৳1290.00`, and no further "Could not send" entries are logged.
